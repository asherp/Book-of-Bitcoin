Here the rule would first bind. BIP110 is a temporary cap on how much data a transaction may carry — the reduced-data limit — so from this chapter on, a transaction whose outputs or witnesses exceed it is not a valid transaction at all. Nodes will not relay it, miners cannot include it, and the passages that would have carried it are simply never written.

Which is what a soft fork always does to this book: it does not change how a passage reads, it changes which passages can exist. Everything before this height stands exactly as written — a data carrier confirmed in an earlier chapter stays confirmed and stays readable, because the chain does not revise. What narrows is the range of what any later chapter may contain.

The inscription entries elsewhere in the contents are the counter-argument in advance: the data they carry rides in witnesses under rules that permitted it, and any reader can see what a limit here would and would not have prevented.
